# 发送通道：坐标、颜色定位与自校验

## 一、核心结论：**全程停在 ADBKeyboard，不要切回讯飞**

早期版本发完会 `ime set` 切回讯飞。后果是**键盘弹起、输入栏整体上移约 890px**，
发送键 y 从 2111 跳到 1276 附近，所有基于坐标/颜色的定位立刻失效
（实测包围盒被撑到 `429x318`、`198x351`，脚本只好拒绝点击）。

**改法**：全程保持 `com.android.adbkeyboard/.AdbIME`。它没有可视键盘，
布局稳定，输入栏不再位移。副作用是**手机无法手动打字**（切回讯飞即可恢复）。

中文/emoji 走广播注入，天然支持 Unicode：

```bash
am broadcast -a ADB_INPUT_B64 --es msg <base64>
am broadcast -a ADB_CLEAR_TEXT          # 清空草稿（发送前先清，防止旧草稿被误发）
```

## 二、坐标会漂，且有两种漂法

| 漂移源 | 表现 |
|---|---|
| ADB Keyboard 的 `{ON}` 条 | 发送键 y 在 **2056 / 2112** 之间跳（差 56px，正好是条的高度） |
| 表情面板开合 | 输入栏整体位移，表情键 y 实测出现过 **2200 / 2275** |

→ **任何坐标都不能写死，发送前必须重新定位。**

## 三、QQ：色彩定位发送键

QQ 发送键是浅蓝实心圆角矩形，谓词：

```python
p[2] > 200 and p[2] - p[0] > 50 and p[1] > 140
```

扫描区 `x ∈ [780, W)`、`y ∈ [1950, 2300]`。实测命中 `192x112`、约 5128 点，
中心 `(939, 2111)`。**尺寸校验**：`N<800 或 BW>300 或 BH>200` 一律拒绝点击。

> 注意：QQ 聊天背景的蓝色贴纸会与按钮连成大包围盒（见过 `441x420`），
> 所以尺寸校验是必须的。

## 四、微信：绿色发送键 + 输入框位置

微信**不暴露节点树**（见另一篇文档），只能整屏截图判色。

- 底部图标行 y ≈ **2275**：🎤`66` · 图片`254` · 相机`449` · 表情包`641` · 😊`800` · ＋`995`
- 输入框：`x ∈ [132, 843]`、`y ∈ [2230, 2330]`，中心取 **(300, 2280)**
- 发送键（有草稿时才出现）：**绿色**，实测中心 **(983, 2225)**、约 `132x84`、2595 点

## 五、自校验：三种判据的成败

| 判据 | 结果 |
|---|---|
| 「点完输入框为空」 | ❌ **假阳性**：`setText` 失败时输入框本来就空，会误报成功 |
| 「消息列表里出现且列表变化」 | ✅ 可用（需能读节点树 → 微信不行） |
| 「无障碍结果文件里出现这条」 | ✅ **最快最准**，QQ 首选 |
| 「发送键颜色消失」 | ✅ 微信首选（绿色 2595 点 → 0 点，分离干净）；QQ 不行（该区域另有蓝色元素，计数降不下来） |

**最终方案**：
- QQ → 注入后色彩定位 → 点击 → **grep 无障碍结果文件**校验
- 微信 → 注入后绿色定位 → 点击 → **复查绿色是否归零**校验

## 六、速度

| 版本 | 做法 | 耗时 |
|---|---|---|
| `qq-fire.sh` | uiautomator dump 定位 + dump 校验（两次 dump，各约 3.7s） | **13~16 秒** |
| `qq-fast.sh` | 色彩定位 + 无障碍文件校验（**零 dump**） | **8~9.5 秒** |

一次 shz 往返本身只有几十毫秒的边际成本，**大头的两次 `uiautomator dump`**。

## 七、无障碍 `setText()` 为什么不用

`ACTION_SET_TEXT` 确实能把中文写进 QQ 输入框（全树搜索能找到），
但 **QQ 不回传输入框的 `text()`**，任何基于回读的校验都会失效；
且 `className("android.widget.EditText").findOne()` 可能选中隐藏的那个。
→ 结论：**发送一律走 ADBKeyboard 广播**，不要用无障碍 `setText`。

## 八、截图一律 JPG

`screencap -p` 只能出 PNG。用 PIL 转 JPG：

```
PNG 843 KB  →  JPG 136 KB（quality=78）
```

多模态读图成本随之降到约 1/6。见 `shot.sh`。
