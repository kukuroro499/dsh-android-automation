# 无障碍（AccessibilityService）读屏通道

比 `uiautomator dump` 快一个数量级，且**不依赖 Shizuku**。本文记录实测结论与坑。

## 一、为什么选它

| | uiautomator dump | 无障碍直读 |
|---|---|---|
| 读一次耗时 | **约 3.7 秒** | **瞬时**（同一次事件里取节点） |
| 依赖 | Shizuku（经常掉线） | 不依赖 |
| 驱动方 | 容器侧反复 spawn | 设备侧常驻脚本 |

## 二、启用（MIUI 实测：这次「settings put」是有效的）

```bash
SVC=org.autojs.autoxjs.v6/com.stardust.autojs.core.accessibility.AccessibilityService
shz "settings put secure enabled_accessibility_services $SVC; settings put secure accessibility_enabled 1"
shz "dumpsys accessibility | grep -A2 'Bound services'"
```

成功标志：

```
Bound services:{Service[label=Autox.js v6, capabilities=41, eventTypes=TYPES_ALL_MASK]}
Enabled services:{{.../core.accessibility.AccessibilityService}}
```

`capabilities=41` = `CAN_RETRIEVE_WINDOW_CONTENT(1)` + `CAN_REQUEST_FILTER_KEY_EVENTS(8)`
+ `CAN_PERFORM_GESTURES(32)`。

> ⚠️ 对比：**通知监听**权限在 MIUI 上 `settings put` 是**无效**的（设置能回读但
> `dumpsys notification` 的 Allowed 列表不认），必须在系统 UI 里手动授权。
> 无障碍这个**有效**。

## 三、常驻脚本设计（dsh-a11y.js）

AutoX 脚本用 `setInterval` 常驻，每 800ms：

1. 写心跳 `a11y.hb`（内容 `Date.now()`）
2. `currentPackage()` → 查表决定写哪个目标文件
3. `textMatches("[\\s\\S]+").find()` 取全部有文本的节点 + `bounds().top`
4. 按 y 排序，逐行 `y=<n> <text>` 写入 bind-mount 文件

容器侧直读 `/home/dsh/shared/a11y-qq.txt`（= 设备的 `/sdcard/dsh-shared/a11y-qq.txt`）。

**看门狗**：心跳 >90 秒未更新判定死亡，重新 `settings put` 无障碍 + 用 intent 拉起脚本。

## 四、四个实测大坑

### 1. 微信完全不暴露节点树 ❗️
```bash
shz 'uiautomator dump /sdcard/dsh-shared/_wx.xml'
# → 总节点: 1，包名分布 [('com.tencent.mm', 1)]，有文本的节点: 0
```
**不是读错窗口**——微信主动屏蔽。所以微信只剩「截图 + 多模态读图」这条路。
QQ 相反，节点树完整可用。

### 2. 悬浮面板会抢「当前窗口」
无障碍/`currentPackage()` 取的是**最顶层窗口**。当 DSH 悬浮面板在前台时，
读到的全是面板自己的内容（实测一次读到 333 个面板节点）。
→ 自动化期间必须让目标 App 真正在前台。

### 3. 空读取会清空结果文件
前台切换的一瞬间会读到**空节点树**，脚本忠于职守地把结果文件写成空，
监听端就会误判成「内容变了」。
→ **修复：空结果绝不覆盖。**

### 4. 残缺读取（更隐蔽）
比「全空」更难防：曾读到「只有群头 + 发送按钮、消息列表为空」的 3 行结果。
它不空，所以躲过了第 3 条的守卫。
→ **建议：写入前要求行数 ≥ 5。**

## 五、AutoX 的存活问题

- MIUI 会反复杀/挂起 AutoX 的 JS 脚本，**这是常态**，不是 bug
- 缓解：`cmd deviceidle whitelist +org.autojs.autoxjs.v6`、`appops set ... RUN_IN_BACKGROUND allow`
- 心跳 + 看门狗能自愈；但**看门狗本身要 Shizuku 才能发启动 intent**，
  所以 Shizuku 掉线时脚本死了就救不回来，需要人工开一次 AutoX
- 脚本文件改名（`dsh-a11y-v7.js`）可绕开 AutoX 对旧文件的缓存

## 六、监听端反模式

监听签名不能简单取「文件末尾 N 行」——**表情面板打开时，面板条目会排在文本列表最后**，
签名就变成在跟踪面板，聊天新消息反而触发不了。
→ 签名前必须先**过滤掉 y > 2260 的面板区域**，只看聊天区。
