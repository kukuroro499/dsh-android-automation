# 点击流程提速调研备忘

设备：小米 24117RK2CC / Android 16 / Shizuku(uid 2000) / dsh 跑在 PRoot 容器
调研时间：2026-09-23
状态：**未实施任何改动**，本文仅为结论与实测数据存档。

---

## 1. 实测成本

| 操作 | 耗时 | 备注 |
|---|---|---|
| 1 次 `shz` 往返 | **650–713 ms** | 每次都要冷启动一个 `rish`(`app_process`) |
| 同一次 shz 内**追加** 1 次 `input` | **~43 ms** | 边际成本。5 次 input 同批只比 1 次多 173ms |
| `screencap -p` | **1030 ms** | 每张 |
| `uiautomator dump` | **3731 ms** | 每张，最贵 |
| `dumpsys window` | 642 ms | ≈ 全是一次 rish 的钱，命令本身很快 |

测法：用 `input keyevent 0`（KEYCODE_UNKNOWN，无副作用）当探针，避免测试本身乱点屏幕。

### 核心结论（与直觉相反）

**`input tap` 本身不慢。** 瓶颈按大小排序是：

1. **我自己读图的模型开销** —— 一张 1MB PNG，未精确量化，但很可能是最大的一块
2. **`uiautomator dump` 3.7s**
3. **每次 shz 的 650ms 冷启动**
4. **`screencap` 1s**
5. `input` 本身（43ms）—— 可以忽略

所以"让 tap 快 40ms"意义不大，**"让我少看图、少往返"才是真正的提速**。

## 3. 自建"常驻守候进程"路线：已试，卡住且有安全风险

**素材是齐的：**

- 设备有 `nc`（`/system/bin/nc`，toybox 0.8.12），支持 `-L`（常驻监听 + 每连接 fork）
- **容器与宿主共享网络命名空间**：容器内直连 `127.0.0.1:8099`（Termux 里的 broker）成功
  → 设备侧只要监听 `127.0.0.1:PORT`，容器就能直连，**每次命令省掉 650ms**

**实测结果：**

1. `nc -L -p 18099 sh` 在 rish 会话里**后台化失败**：命令挂住，60s 后超时被杀
2. 副作用：**把 broker 连接搞重置了一次**（`ConnectionResetError: [Errno 104]`）
   —— 已确认恢复，`shz-doctor` 三项全绿；野进程已清理

**放弃这条路的真正原因（安全）：**

一个监听 `127.0.0.1` 的**裸 shell** 守候进程，等于给这台设备上**任何 App** 一个
`uid 2000(shell)` 的 shell。shell 能读 `/sdcard`、能 `pm install`。这是实打实的提权面，
比 `/data/data` 那道墙还糟。

**结论：守候进程可以做，但必须是"固定功能"的** —— 只暴露 `tap/swipe/key/screencap/dump`
这几个动作，绝不提供任意 shell。

## 4. 三条路线

| 路线 | 收益 | 成本/风险 |
|---|---|---|
| **A. 零成本优化**（推荐先做） | 省掉每次 3.7s 的 dump、降低读图开销 | 无。不装任何东西，不改架构 |
| **B. 固定功能守候进程** | 消除 650ms/步 | 需先解决后台化；要设计成无任意 shell |
| **C. 接入 uiautomator2** | dump/screenshot 从 3.7s/1s 降到几百 ms，API 成熟 | 最彻底也最费事，要先啃"没有 adb"的接入问题 |

### 路线 A 的具体做法

1. **坐标缓存**：`uiautomator dump` 一次，把控件表存成 JSON，后续 tap 全用缓存坐标
   —— 省掉每次 3.7s
2. **截图先裁剪/缩放再读**：用 `ffmpeg -vf crop=...` 只裁关心的区域
   —— 图小 = 我读得快、token 少（已验证有效：`col5.png` 200×620 比整屏 1080×2400 便宜得多）
3. **全流程压进单次 shz**：已实现（见 `wx-send.sh`）

### 关键工具经验

- **`uiautomator dump` 只导出"持有焦点"的那个窗口**。DSH 面板抢焦点时只能 dump 到 DSH 自己；
  让目标 App 到前台（`am start`）就能拿到目标 App 的控件树
- **中文/emoji 必须走 ADBKeyboard 广播 `ADB_INPUT_B64`**：`input text` 遇非 ASCII 会抛
  NullPointerException 并**静默失败**
- 收起表情面板用 `input keyevent 4`(BACK) 比点按钮可靠（面板开/关两态下按钮只差 ~100px，易点错）
- 让目标 App 到前台：`am start -n <pkg>/<activity>`，若任务已在后台会"带到前台"而不重启
- DSH 面板是 **freeform 窗口**；它被切成 fullscreen 时目标 App 完全不可点。
  DSH 有前台服务 `HarnessService`(isForeground=true)，所以把目标 App 拉到前台**不会**冻住我这边的进程
